# Pre-Engagement — Notes to Remember

## 1. What is Pre-Engagement?

**Pre-engagement** is the stage that happens **before the actual penetration test**.

### Main Purpose

* Understand what the **client wants tested**
* Define the **scope and goals**
* Agree on **rules, timing, communication, risks, and legal permission**
* Prepare the **required documents**

---

## 2. Main 3 Components

Remember the order:

> **Scoping Questionnaire → Pre-Engagement Meeting → Kick-Off Meeting**

Before discussing these in detail, an **NDA (Non-Disclosure Agreement)** should be signed.

---

## 3. Important Legal Point

The tester must know **who is authorized to hire/approve the penetration test**.

**Written permission is essential** because testing without proper authorization could be illegal.

---

## 4. Important Documents

| Document                               | Purpose                           |
| -------------------------------------- | --------------------------------- |
| **NDA**                                | Confidentiality                   |
| **Scoping Questionnaire**              | Understand client requirements    |
| **Scoping Document**                   | Summarize scope/information       |
| **Penetration Testing Proposal / SoW** | Formal agreement                  |
| **Rules of Engagement (RoE)**          | Rules for conducting the test     |
| **Contractors Agreement**              | Required for physical assessments |
| **Reports**                            | Document test results             |

### Easy Memory

```text
NDA → Scope → Contract → RoE → Test → Report
```

---

## 5. Scoping Questionnaire

The questionnaire is sent **after initial client contact**.

### It Determines

* Type of assessment required
* IPs, domains, hosts, and applications in scope
* Number of users and locations
* Testing objectives
* **Black-box / Grey-box / White-box**
* **Evasive / Non-evasive** testing
* Activities that are **out of scope**

### Main Idea

> **Scoping = WHAT are we testing?**

---

## 6. Pre-Engagement Meeting

The tester and client discuss the project **in detail**.

### Important Topics

* Goals
* Scope
* Testing type
* Methodology
* Locations
* Time and dates
* Third parties
* Risks
* Restrictions
* Communication
* Reporting
* Payment

### Main Idea

> **Pre-engagement meeting = Agree exactly how the test will be conducted.**

---

## 7. Rules of Engagement (RoE)

The **RoE defines the rules that must be followed during the penetration test**.

### Major Areas

* Purpose & goals
* Scope
* Contacts & communication
* Dates & times
* Testing type & location
* Methodology
* Evidence/data handling
* System backups
* Incident handling
* Reporting
* Retesting
* Liability & disclaimers
* Permission to test

### Main Idea

> **RoE = RULES we must follow while testing.**

---

## 8. Kick-Off Meeting

The kick-off meeting usually happens **after the contracts are signed**.

### Participants

* Client contacts
* IT/security/technical staff
* Penetration testers
* Project/management staff

### They Confirm

* How testing will happen
* Communication methods
* Emergency contacts
* Risks
* What happens if a critical vulnerability is found

---

## 9. Critical Vulnerability

If a **critical vulnerability** is discovered:

1. Testing may be **paused**
2. Client is **notified**
3. An **emergency report** may be created

> **Usually, DoS testing is NOT performed.**

---

## 10. Physical Assessment

If the penetration test includes **physical testing**, a **Contractors Agreement** is required.

This is because physical intrusion involves **additional legal considerations**.
